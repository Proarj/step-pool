# StepPool

A private step challenge for one group of friends. Everyone stakes the same
number of virtual coins each day, and whoever misses the group's step goal
loses their stake to the people who hit it. Design:
`docs/superpowers/specs/2026-10-10-steppool-design.md`.

## Requirements

- Node 24 (`nvm use` picks it up from `.nvmrc`)

## Tests

```bash
nvm use
npm test          # SQL tests run the real migrations in PGlite: no Docker, no accounts
npm run typecheck
```

## Database

All backend logic is in `supabase/migrations/`:

| File | What it does |
|---|---|
| `…01_schema.sql` | Tables, IST clock helpers, sign-up trigger (+1,000 coins), write lockdown |
| `…02_groups.sql` | `create_group`, `join_group`, `update_group_settings` (from tomorrow), `leave_group` |
| `…03_steps.sql` | `upload_steps`: only for today in IST |
| `…04_scoring.sql` | `score_pending_days`: settles every unscored day before today |
| `…05_read_access.sql` | Row Level Security: members see their group and its people only |
| `…06_cron.sql` | Runs scoring every hour on the hour IST (Supabase only) |
| `20261011000001_stakes.sql` | Rules update: per-person stakes (`set_my_stake`), losers pay winners in proportion to the winners' stakes (`day_transfers`), no wallet (`group_totals` can go negative). Wipes all game data |

**Rules in one paragraph:** everyone in a group shares one daily step goal and
picks their own stake (1–1,000 coins). At 12:00 AM IST, each person who missed
the goal pays each person who hit it `floor(loser stake × winner stake / total
winners' stake)`, and rounding stays with the loser. If everyone or nobody hit
the goal, nothing moves. Totals start at 0. Changes to the goal or a stake, and
leaving, take effect the next day.

Apply them to a Supabase project:

```bash
npx supabase login
npx supabase link --project-ref <your-project-ref>
npx supabase db push
```

## The app

An Expo SDK 57 app in `src/`, with expo-router screens in `src/app`. It talks to
the Supabase project set in `.env.local` (copy `.env.example`). The native
folders `ios/` and `android/` are generated by `npx expo prebuild` and are not
committed.

### Android (APK, no store, no account)

```bash
nvm use
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
npx expo prebuild --platform android --clean
(cd android && ./gradlew assembleRelease)
# → android/app/build/outputs/apk/release/app-release.apk
```

Send the APK by Google Drive, WhatsApp or similar. On the phone, open it and
allow "Install unknown apps" when asked. Then, in StepPool, tap **Set up step
access**.

### iPhone (free Apple account, re-run every 7 days)

Needs a Mac with Xcode, and the iPhone plugged in with Developer Mode on.

```bash
nvm use && npm ci
cp .env.example .env.local   # fill in the two values
IOS_BUNDLE_ID=com.<yourname>.steppool npx expo run:ios --device --configuration Release
```

The first time, pick your **Personal Team** when asked for a signing team. On
the iPhone, trust the developer under Settings → General → VPN & Device
Management. Free builds stop opening after 7 days, and the app reminds you on
day 6: plug the phone in and run the same command again.

### After a fresh `supabase db push`

In the Supabase SQL editor,
`select jobname, schedule, active from cron.job;` should show
`score-pending-days | 30 * * * * | true`.
In Authentication → Sign In / Providers, keep only **Google** enabled.
